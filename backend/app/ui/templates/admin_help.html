База знаний администратора

Коротко: деньги живут только здесь (ledger). Панель 3x-ui и CCTV — исполнители и источники телеметрии.

1. Продукты и тарифы

  • Код — служебный (vpn-vless-minute), меняется только до первых продаж.
  • Название для клиента — то, что видно на лендинге и в кабинете.
  • Тарификация: посекундно / поминутно / почасово / в день / в месяц / разово. Секунды и минуты биллятся автоматически по телеметрии; месячные — через заявки и мосты (CCTV).
  • Цена — в копейках за один тик тарификации: 150 = 1.50 ₽ за минуту; для «посекундно» например 3 = 0.03 ₽/сек (~1.8 ₽/мин).
  • В продаже — выключай вместо удаления (услуги клиентов не осиротеют). WireGuard пока нет в железе → держи выключенным.

2. Ноды (серверы услуг)

  • 3x-ui: тип управления «панель 3x-ui», в доп. параметрах JSON: inbound_id, sni, pbk, sid, fp. Логин/пароль панели шифруются при сохранении.
  • WireGuard: тип «SSH + wg-peer», подсеть для выдачи IP, публичный ключ сервера, хост/порт для клиентов.
  • Нода «не активна» → новые услуги на неё не выдаются, существующие продолжают работать.

3. Жизненный цикл услуги

  • Клиент нажимает «Подключить» → создаётся услуга в статусе «выдаётся» → задача provisioning создаёт аккаунт на ноде → «активна».
  • Смотреть ошибки выдачи: «Задачи выдачи (provisioning)» — колонка «Ошибка».
  • Телеметрия (heartbeat) от ноды создаёт сессию; пока сессия идёт, каждые N секунд/минут (тик продукта) списывается цена тика.
  • Баланс кончился → услуга «приостановлена», клиент в панели гаснет сам (ему заранее пушится оплаченный конверт expiry).
  • Клиент пополнил и нажал «возобновить» → услуга снова «активна».
  • Ручное вмешательство: «Услуги клиентов» → редактирование статуса/имени/конфига.

4. Деньги

  • Пополнения клиентов приходят заявками («Заявки на пополнение»): одобрить = зачислить в ledger, отклонить = отклонить. Повторное одобрение невозможно (идемпотентность).
  • Ручная корректировка: API /api/v1/admin/wallets/{id}/credit с уникальным idempotency_key (для исключительных случаев).
  • Ledger не редактируется и не удаляется — это финансовый журнал. Ошибки исправляем новой операцией, а не правкой старой.

5. Если что-то сломалось

  • Услуга висит «выдаётся» → задачи provisioning → ошибка → чиним ноду/панель → сброс задачи: UPDATE provisioning_tasks SET status='pending', attempts=0 WHERE status='error'; (в psql контейнера db).
  • Клиент не работает, а баланс есть → «VPN-аккаунты»: статус; затем нода/панель вручную.
  • Биллинг упал → клиенты в панели живут до оплаченного конверта expiry и гаснут сами; после подъёма синхронизация продолжится.
